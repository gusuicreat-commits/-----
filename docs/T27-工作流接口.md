# T27 六步工作流 API

新流程与旧 `/run` 分离。新流程始终 `render_mode=standard`，`production_engine` 决定实际渲染；`director_recipe` 决定讲解内容。精细制作不会强迫尺度片加入运动或拆解，也不会静默回退 Three.js。使用新流程的项目不能经旧 `/run` 绕过预览审核。

1. `POST /api/projects {name,brief}`；上传复用 `/docs`(PDF)、`/assets`(图片/视频)、`/model/step`(STEP/STP)，也可 `/api/demo/seed` 创建带标注的预置示例。
2. `PATCH /api/projects/{pid}/workflow/brief {brief,target_s,engine,content}`。`target_s=10..120`；`engine=threejs|blender`；`content=auto|scale|motion|structure`。
3. `GET /api/workflow/capabilities` 返回 engines、contents、provider。provider 由通用模型适配器提供，含 configured/provider/model/mode/base_url/vision_supported/error，不含密钥。配置存在不等于服务探测成功。
4. `POST /api/projects/{pid}/workflow/preview {replan:true}` 后台仅准备模型、调用共享 planner/Skill、校验和无声时间线。没有 TTS、整片渲染、合成。返回 `{run,state:"previewing"}`。
5. `GET /api/projects/{pid}/workflow` 轮询；原方案从 `/shotlist` 读取。`preview.timeline_url` 是独立 `preview-timeline.json`，可交给现有播放器。Three.js 为实时构图预演。Blender 逐镜调用现有 `render_shot.py --still-at`，真实生成 640×360 的中间关键帧，位于 `renders/workflow-preview/{plan_revision}/{sid}`。`preview.keyframes_status=rendering|ready|realtime`，`preview.keyframes=[{shot,url,engine,kind}]`；实拍条目 engine=source，不能冒充 Blender 结果。精细关键帧失败则工作流 error，不能点击制作。
6. `POST /workflow/produce {plan_revision}` 只接受当前 preview_ready 的修订，重新校验不允许 force；从 TTS 开始制作当前分镜，绝不再次规划。严格保留已预览时长，配音过长则停止并提示缩短台词/调整时长重预览。

`GET workflow` 核心字段：state、current、plan_revision、can_preview、can_produce、can_download、brief、target_s、engine、content、provider、issues、preview、exports、error。state 为 idle / previewing / preview_ready / blocked / stale / producing / production_done / error。只有 production_done 且 revision 当前时导出可见。exports 为 `{mp4,project,sources,report}`，分别 MP4、项目 ZIP、HTML 来源报告、JSON 报告。

局部修改复用 `/shots/{sid}/revise {instruction}` 和 `PATCH /shots/{sid} {narration?,params?,duration_s?,review?}`。修改后旧预览和旧导出失效；调用 `POST /workflow/preview {replan:false}` 重校验并重新预览当前镜头，保留人工修改。整体改想法则 brief + replan:true。制作与修改、旧流水线共用项目锁；制作中拒绝编辑/重复启动。失败会释放锁。

精细引擎现有边界：参数化模型；楼层/足球场类比；model_orbit、motion、exploded、title、outro、data_card 等；真实图片视频和创意/信息图仍由网页统一合成。STEP 忠实精细渲染、weld_macro、其他比例参照物显式阻断。T26 特殊多角度路径未接入本流程。缺 Blender 显式阻断，不将 Three.js 声称精细制作。

修订 fingerprint 覆盖 brief、设置、模型说明、rig、事实、素材、分镜，以及 docs/assets/model 文件内容 SHA-256。文件 digest 缓存以 size/mtime/ctime/inode 共同失效；即使同大小且恢复 mtime 的内容替换也会重新哈希。更改事实、素材、模型、台词、时长或审核字段均需重新预览。项目最终 MP4/ZIP/报告与过期 preview 文件的 `/files` 访问也拒绝，防止前端旧链接冒充新结果。ZIP 包含当前方案、时间线、报告、输入资料/素材/模型，不包含渲染缓存。

验证：`backend/.venv/bin/python -m pytest backend/tests/test_workflow.py ...` 使用 mock planner 和 renderer，验证预览不产生影片、编辑失效、当前方案制作、并发、失败释放锁、引擎边界、单帧命令。离线测试不证明真实模型/Blender/配音/整片制作成功。

长片新流程（production_engine 已选择、target_s≥30）将共享 Skill 配方作为主题及证据约束，保留主题绑定但移除固定三镜 sequence；读取 cinematography.md 的通用指导，安排6–9镜，按现有 model_orbit 参数改变角度与距离。不会宣称执行T26特殊path。旧配方与短片保持原行为。

制作成功生成 deliverables.json，绑定本次 run、plan_revision 及每个最终导出的 size/SHA-256；后续导出文件缺失或被替换会失效。mux 未更新旧 final.mp4 时拒绝发布。只阻断最终 final.mp4/报告/ZIP，内部 Blender 背景缓存与生产所需文件仍可读取。

兼容高级工作室：未发布或过期时 `GET /api/projects/{pid}/report` 返回200和 `{}`，让基本资料刷新继续工作并隐藏旧报告；`/files/{pid}/report.json`、HTML报告和最终MP4仍返回409。

新生成方案出现镜头级阻断时，最多自动调用两轮共享 planner.repair 并在每轮后完整复验；不降低规则，也不自动改 human_edited/approved 镜头。`replan:false` 仅校验预览，不自动改镜。`repair_attempts` 记录本轮次数；失败或两轮后仍有阻断则明确停止/blocked。新流程的自然语言 revise 标记 human_edited；自动修复保留原镜头时长。copywriting.md 与 cinematography.md 实际进入新流程模型上下文，要求连续讲解、减少镜头报幕、事实与观察分句并分别支持。

参数化模型记录构建输入（已确认参数值与 parametric.py/rig.py 内容）签名、实际 GLB/rig digest。未知签名的旧模型或参数/输出不匹配时，即使 `replan:false` 也重建 GLB/rig 和 dims_check；制作前再次阻断未同步模型，不会把新事实叠在旧尺寸模型上。现有 STEP 不按参数化模型重建。

服务重启后，持久化 previewing/producing 却没有本进程 worker 的任务，GET workflow 自动标为 error/interrupted 并隐藏导出，提示重新预览，可重新开始；有活动 worker 的任务继续保持运行状态。
