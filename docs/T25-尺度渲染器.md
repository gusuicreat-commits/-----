# T25 应用尺度渲染器

`blender/scale_film.py` 是独立应用入口。复用 `derive_dimensions()`、`build_crane()` 和T24已认可的涂装/细地面/冷暖侧光/薄雾配方；不修改T24及公共Blender文件。画面仍是参数化结构示意，非厂家CAD或实物验证。声音、数字、尺寸线、字幕、来源说明均由后端合成。

## 调用

```sh
/Applications/Blender.app/Contents/MacOS/Blender --background --factory-startup --python-exit-code 1 --python blender/scale_film.py -- --config /absolute/config.json --out /absolute/outdir --stills
```

去掉 `--stills` 才执行正式全片渲染和H264编码。需要PATH中有ffmpeg；本轮只做低分辨率静帧，没有自行执行正式全片。入口对非法输入抛异常，配合 `--python-exit-code 1` 返回非0。所有输出只在指定out内。

```json
{
  "version": 1,
  "width": 1920,
  "height": 1080,
  "fps": 30,
  "facts_file": "/absolute/normalized-facts.json",
  "shots": [
    {"id":"s1","role":"detail","start":0,"end":4},
    {"id":"s2","role":"hero","start":4,"end":9},
    {"id":"s3","role":"compare","start":9,"end":15}
  ]
}
```

输入必须是版本1；正整数偶数宽高、正整数fps；三个唯一非空id；顺序为detail→hero→compare；从0连续开始，每镜正时长；切点对齐帧网格；总时长15–30秒。不会把15秒或104m写死为实际成片内容。104/51只作为恢复已审T24摄影机位的归一化参考，不是缺参默认值。

facts_file是绝对路径，内容为 `{ "facts": [{"id":"F_girder_length","value":132,"unit":"m","status":"confirmed"}, ...] }`。**主梁长度F_girder_length和整机高度F_overall_height必须提供confirmed/verified的有限正数**，绝不回退104/51。其余F_span/F_lift_height/F_girder_height/F_wheel_count可缺失，由既有derive_dimensions规则派生，manifest同时保留 `dims.assumed` 和 `assumptions`。任何已提供的这些尺寸事实如果未确认、重复、非有限、布尔/字符串、非正值或错误单位即拒绝；车轮数必须整数且≥4。单位可省略（约定规范化为米），显式尺寸单位仅接受m；几何冲突继续由derive_dimensions拒绝。不会把派生参数写成confirmed。

## 输出契约

`--stills` 输出三镜中点 `stills/01-detail.png`、`02-hero.png`、`03-compare.png`，以及 `projection.json`、`manifest.json`。正式模式也保留这三张关键帧，另输出无声 `noaudio.mp4`。正式运动帧放在每次调用独有的 `.scale-film-frames-*` 临时目录，编码后自动清理（异常时也清理）；不删除其他调用、关键帧或应用cache。后端负责缓存策略。

正式时间线以前两镜每帧真实机位渲染，第三镜锁定正交，直接复用已生成的compare关键帧覆盖该镜的所有时间线帧。`manifest.frames` 区分最终时间线帧、运动帧独立渲染次数、保留关键帧、实际渲染操作数、静止复用帧数；不要把它们混为一项。标准4+5+6秒/30fps时：450时间线帧，270次运动渲染+3次关键帧渲染=273次渲染操作，末镜180帧复用compare关键帧。stdout进度为 `已完成第 n/N 帧`，完成后有 `SCALE_FILM_COMPLETE` JSON摘要。

`projection.json` 为第三镜顶层单组投影：

```json
{
  "version":1,
  "coordinate_system":"normalized_top_left",
  "shot_id":"s3",
  "field":{"left":0.2,"right":0.8,"top":0.1,"bottom":0.7},
  "girder":{"left":0.22,"right":0.78,"top":0.8,"bottom":0.9},
  "length_m":132,
  "reference_length_m":105,
  "reference_width_m":68,
  "projection":"ORTHO"
}
```

上述rect数字只作schema示例。实际rect从未变形的米制球场平面、实际主梁网格包围框经Blender相机投影得到，坐标原点左上；后端据此画尺寸线和标签。球场为105×68m标准化示意，非真实场地。主梁仍有原模型的肋板/栏杆/顶架等示意附件，rect为可见几何包围框。

manifest记录实际dims、assumptions、三镜起中终机位、每次渲染记录/耗时、config和facts的绝对路径及SHA-256、时间线计数、总计时、几何来源和边界。干净图像没有来源字样，后端必须在最终发布片持续合成来源/示意性质。

## 摄影适配

近景相机横向位置随主梁长度缩放，视点绑定真实派生梁顶/梁底，适配高度和截面变化。Hero先按长高适配距离，再对主梁、小车、支腿组件包围点做透视投影；必要时仅后退水平机距，保留低机位，直到主要设备处于5.5%画面安全框；轨道可延伸出画面。104m×51m的中点机位保持T24的(84,-143,5.75)m，45mm镜头。正交镜头按主梁实际长度和画幅扩大视野，保证球场/主梁不变形、同一尺度、互不重叠并留底部来源空间。相机显式HORIZONTAL sensor_fit使各画幅的数学投影和Blender一致。

## 本轮验证

- `backend/.venv/bin/python -m pytest backend/tests/test_scale_film_geometry.py -q`：114项通过，包含非法输入/NaN/时序、同尺度比例与留白、多长度高度画幅及镜头起中终取景。
- 960×540静帧：render-dev/104与132各三张，Blender均退出0，主控已查看Hero和132比较镜头并认可构图。实图显示132m梁确实长于105m球场，均无裁切。
- 仅length/height的132-minimal又渲三张，退出0：派生span=112.2m、lift_height=44.88m、girder_height=6.5m、wheel_count=16；四项均列assumed。
- 实际Blender入口对空facts退出1，日志为missing confirmed dimensions，没有建场或渲染，也没有默认104。

开发产物在 `outputs/T25-scale-film/render-dev/`。这验证了入口、静帧和数学；正式编码、HTTP链路与最终音画合成仍由主控后续验收。
